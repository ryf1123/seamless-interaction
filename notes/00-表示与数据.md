# 00 表示与数据：258 维是怎么来的，数据是怎么造的

这一页讲清两件事：**动作用什么表示**、**训练数据从哪来**。
两件事都有一个不显然的设计决策，各配了图和数字。

---

## 1. 动作表示：为什么是 258 维

Seamless Interaction 用 SMPL-H 表示身体和手（论文 §3.1）：

```
全局朝向 φ ∈ R³ + 关节姿态 θ ∈ R^{51×3} + 体型 β ∈ R^{16}
```

数据集里主要是**上半身**手势，所以论文丢掉 8 个腿部关节，
剩下 **51 − 8 = 43** 个关节。每个关节用 **6D 旋转**表示 → **43 × 6 = 258**。
本项目沿用完全相同的维度，`si/skeleton.py` 里 `BODY_DIM == 258` 是断言出来的。

丢掉的 8 个腿部关节：`left_hip(1) right_hip(2) left_knee(4) right_knee(5)
left_ankle(7) right_ankle(8) left_foot(10) right_foot(11)`。
渲染时它们画成灰色，提醒「这部分数据里永远不动」。

### 为什么是 6D 而不是轴角或四元数

轴角和四元数对旋转的表示都**不连续**：同一个旋转有多个等价表示
（轴角的 θ 和 θ+2π、四元数的 q 和 −q），网络回归时会在两个表示之间反复横跳。
6D 表示（Zhou et al. 2019）取旋转矩阵的**前两列**，解码时 Gram-Schmidt 正交化回矩阵：

```
a₁, a₂ = d6[:3], d6[3:]
b₁ = a₁ / ‖a₁‖
b₂ = normalize(a₂ − ⟨b₁, a₂⟩ b₁)
b₃ = b₁ × b₂
R  = [b₁ b₂ b₃]
```

这个映射是满射且连续的，所以没有横跳。自测（`python -m si.rotation`）：
随机 7×5 个轴角转 6D 再转回矩阵，最大误差 **3.3e-16**。

单位旋转的 6D 是 `[1,0,0, 0,1,0]`——这个数在后面看特征热力图时会反复出现。

### 从 258 维反查到具体关节

`si.skeleton.body_slot(name)` 给出任意关节在 258 维里的下标区间：

| 关节 | SMPL-H 关节号 | 在特征里的位置 |
|---|---|---|
| `head` | 15 | `feat[:, 36:42]` |
| `left_shoulder` | 16 | `feat[:, 42:48]` |
| `left_elbow` | 18 | `feat[:, 54:60]` |
| `right_elbow` | 19 | `feat[:, 60:66]` |
| `left_wrist` | 20 | `feat[:, 66:72]` |
| `right_index1` | 37 | `feat[:, 168:174]` |

写文档时**不要只写「258 维」**，要能指到具体下标——这是本项目的文档标准之一。

### 中间插一层：29 个有名字的控制自由度

直接在 258 维里手写手势没法读。`si/pose.py` 插了一层**控制向量**，每一维都有名字：

```
spine_pitch/yaw/roll, neck_pitch/yaw/roll, shoulder_shrug,
{L,R}_sh_abduct/sh_flex/sh_rot, {L,R}_el_flex, {L,R}_wr_flex/wr_dev,
{L,R}_{index,middle,pinky,ring,thumb}_curl
```

共 **29 维**。合成规则是固定欧拉序 `R = Rz(绕前后轴) @ Ry(绕上下轴) @ Rx(绕左右轴)`，
左右侧的 y/z 轴符号相反（镜像）。

**踩过的坑**：第一版里绕 y 轴的角度直接用了 `+sgn·flex`，结果「屈曲为正」
在左臂是向前、在右臂是向后——`other`（指向对方）这个手势的手指向了身后。
修复是把 y 轴角统一取 `−sgn·flex`，于是「屈曲为正」在两侧都表示**向身体前方**。
这类坑只有把侧视图画出来才看得见，正视图里完全正常。

静息姿态（`HOME`）：肩外展 −1.35 rad（从 T 字姿势把手臂放下 77°）、
肘屈 0.40 rad、手指微曲 0.25 rad。FK 出来手腕在 `(±0.31, −0.06, 0.14)` 附近，
大致是站立时手自然垂在髋部前方。

## 2. 数据：为什么要自己造

真实 co-speech gesture 数据集（BEAT、SHOW、Seamless Interaction）都能下，
但**回答不了这个项目最想问的问题**：文本条件到底贡献了什么？
因为在真实数据里，语义手势和语音韵律是纠缠的，你没法把「语义」这一路单独关掉再看差多少。

所以数据是按**已知规则**造的（`si/gesture_expert.py`），三路叠加：

```
ctrl(t) = 静息 + idle(t) + beat(t)·(1 − w_sem(t)) + semantic(t)
```

| 成分 | 驱动源 | 幅度（RMS, rad） | 只看音频能不能推出来 |
|---|---|---|---|
| idle 摇摆 | 2 个 0.13–0.5 Hz 随机相位正弦 | 0.018 | 不需要（本来就是噪声底） |
| beat 节拍 | **语音包络的局部极大** | 0.054 | ✅ 能 |
| **semantic 语义** | **词**（13 类） | **0.266** | ❌ **不能** |

语义那一路的幅度比另外两路大一个量级——这不是随便设的，是为了让
「模型有没有学会语义手势」在指标上是**可分辨**的。

![三路分解](../docs/figs/01_decomposition.png)

### 13 个语义类别

`self`（指自己）、`other`（指对方）、`big` / `small`（比大小）、
`negate`（摇头否定）、`affirm`（点头肯定）、`up` / `down`（方向）、
`count1/2/3`（数手指）、`shrug`（耸肩）、`around`（划圈表示「全部」）。

![手势图谱](../docs/figs/01_gesture_atlas.png)

触发词表在 `si/corpus.py` 的 `SEMANTIC_LEXICON`：
`big ← {big, huge, large, enormous, massive}`，`self ← {i, me, my, mine, myself}`，依此类推。

**一个刻意的偏离**：真实数据里语义手势是**稀有且长尾**的
（Seamless Interaction 论文 §4.4.3 明说这是难点）。
本项目的语料里语义词占了约 40% 的词、覆盖约 56% 的帧——**故意过采样**，
否则 400 句的规模下这个效应根本量不出来。
第七环会专门做「把某一类压到 1% 还学不学得到」的实验，那才是对长尾的正面回答。

### 语音：逐词合成拿到精确的词级对齐

真实数据里词级时间戳靠 WhisperX 强制对齐（论文 §3.4）。
本项目用 macOS 自带的 `say`，但**整句合成拿不到时间戳**。
解决办法是**一个词一个词地合成，裁掉首尾静音，再按固定 45 ms 间隔拼接**——
于是每个词的起止帧是我们自己定的，对齐误差为零。

代价是韵律不自然（没有连读，重音是逐词的）。这个取舍是明确的：
本项目研究的是「语义手势的类别和时机」，对齐精度比韵律自然度重要得多。

```
        词       类别    起(s)    止(s)     帧 @30fps
      mine     self   0.000   0.439      0–14
      said     None   0.483   0.876     14–27
       yes   affirm   0.921   1.372     27–42
       ...
      down     down   4.185   4.549    125–137
```

**踩过的坑**：第一版把 `say` 的输出直接缓存成 `.wav`，进程被中断时留下半个文件，
之后每次读都报 `No 'data' chunk marker`。修复是**原子落盘**（写 `.part` 再 `rename`）
＋ 读之前先 `sf.info` 探一下，坏了就删掉重合成。

**另一个坑**：`sf.write(path.with_suffix('.part'), ...)` 会因为扩展名不是音频格式而报错，
要显式传 `format="WAV"`。

### 并行预热把建库从十几分钟压到 2.5 分钟

`say` 是子进程，瓶颈在进程启动而不是 CPU，所以先把
（词 × 说话人）的笛卡尔积用 8 线程池一次性合成好，再串行拼句子。

```
$ python -m si.dataset 400
TTS 缓存预热：新合成 570 个 (词, 说话人) 组合
写出 data/toy  400 句 / 58702 帧 / 32.6 分钟
  train: 320 句   val: 40 句   test: 40 句
```

5 个说话人（Samantha / Alex / Daniel / Karen / Tom）当 person ID 用，
对应论文里走 AdaIN 全局条件的 style 输入。
