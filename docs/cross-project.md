# 五个项目撞到的同一批墙

同一台 Mac mini、同一个人、同一套纪律，五个方向：

| 项目 | 链路 | 靶心问题 |
|---|---|---|
| [sonic](https://github.com/ryf1123/sonic) | 动捕 → 重定向 → RL 跟踪 → 泛化 | 人类数据只提供「目标长什么样」，物理由 RL 在机器人自己身体里学 |
| [starvla](https://github.com/ryf1123/starvla) | 桌面仿真 → 脚本专家 → 视觉-语言-动作策略 → 闭环成功率 | 语言到底有没有在起作用 |
| **seamless-interaction**（本项目） | 文本 → TTS → 条件 → flow-matching DiT → SMPL-H | text 到底贡献了什么（节奏 vs 语义） |
| facial | 表情源 → 电机 → 仿生脸 → 视觉回读 | 从人的表情到这张脸的电机，难在哪一步 |
| rsi-robot | （刚开始） | — |

四个跑起来的项目，任务、模态、算法全不一样，**却反复撞到同一批墙**。
这一页把它们并排放，因为**能被四个独立任务重复撞到的东西，比任何单个项目的结论都值钱**。

---

## 墙 1：代理指标和主指标在「不坏的区间」里会脱钩

| 项目 | 代理指标怎么动 | 主指标怎么动 |
|---|---|---|
| seamless | val loss **降 25%**（一路降到最低） | SemAcc **掉 13 个百分点** |
| starvla | val L1 好 **16%** | 闭环成功率好 **7 倍**（10% → 72.5%） |
| facial | val MSE 降 **35 倍**、雅可比误差降 **6.2 倍** | ExprAcc 只涨 **1.4 个百分点** |
| sonic | 关节奖励 0.991 | 末端关键点误差差 **3 倍** |

四个项目、四种代理指标（回归 loss / L1 / MSE / 关节奖励），**全部脱钩**。
starvla 那一栏尤其要注意：代理指标和主指标**同向**，但幅度差了两个数量级——
「方向对」根本不够用。

facial 那边给出了目前最精确的表述：

> 代理指标能把**坏的**和**不坏的**分开，不能在**不坏的**里面排序——
> 而实际要比较的配置恰恰都是不坏的。

这解释了为什么四个项目都在同一个地方翻车：早期调试时代理指标很好用（它能告诉你有没有搞砸），
一旦进入「几个都能跑的配置里选一个」的阶段，它就失效了。

**共同的对策**：主指标必须是**任务级**的，并且每次比较都要跑它，不能用代理指标代跑。
代价是慢——seamless 一次 SemAcc 评测要采样 40 条句子，starvla 要跑 40 局闭环，
sonic 要 rollout，facial 要过检测器。**这个价钱必须付。**

## 墙 2：看起来是模型的问题，其实是任务设计的问题

| 项目 | 现象 | 真因 |
|---|---|---|
| starvla | 「有序」的语言编码器训完退化成词袋（换语序的余弦相似度 0.99993） | 第一版任务里**颜色集合就足以定位目标**，语序不携带信息 |
| seamless | 确定性回归完胜生成式（98.5% vs 64.2%） | 数据给定条件后**动作几乎唯一**（条件变异 3.37 cm），回归贴着噪声底 |
| seamless | count1/2/3 三类几乎判不出来 | 三个原型在平均关节距离上只差 **0.33 cm**（只有手指不同） |
| seamless | 音频条件加不加都一样 | 语音是**逐词拼接**的，包络峰就在词中间，文本已经给了精确时间 |
| facial | anger 的识别率是 **0.0%** | 执行器**缺皱眉肌**——一张物理上做不出愤怒的脸 |

starvla 的那句话是这一类的总结：

> **如果任务本身不需要某种信息，模型就不会去表示它，无论你给它多强的架构。**

seamless 把它推广了一步：**如果任务本身不具备某种性质（多峰性），
那么依赖这个性质的方法（生成式）就不会有优势**——这不是模型的失败，是前提不成立。

**共同的对策**：动手改模型之前，先量一个「这个任务到底有多难 / 携带多少信息」的数。
facial 的做法最彻底：**在写模型之前**先把上限和下限量出来，因此在写第一行模型代码前
就抓到了「缺皱眉肌」和「训练/评测观测条件不一致」两个错误，代价是几分钟。

## 墙 3：没有上限和下限，任何分数都读不懂

| 项目 | 主指标 | 下限 | 上限 |
|---|---|---|---|
| seamless | SemAcc | 随机 **7.7%** | 真值 **100%** |
| seamless | 反馈 F1 | 同密度随机撒点 **0.41** | 真值 **0.93** |
| seamless | BeatAlign | 同密度随机 **0.52** | 真值 **0.66**（可用区间只有 0.14 宽） |
| facial | ExprAcc | 随机电机 **12.7%** | 人脸检测器 87.0% / 这张脸的物理天花板 **81.7%** |
| starvla | 闭环成功率 | 瞎猜 ≈ **1/3** | 专家 **100%** |
| sonic | 跟踪误差 | — | 参考本身的可行性（残差模式抬到 98% 证明参考可行） |

seamless 的 BeatAlign 是最极端的例子：**所有模型的分数都是 0.80，高于真值的 0.66**——
因为它们撒点够密。不量下限根本看不出这个指标已经废了。

facial 更进一步区分了**两条上限**：检测器在人脸上的 87.0%，和这张脸物理能做到的 81.7%。
中间 5.3 个百分点是「具身差距」，是硬约束，不是模型的错。

**共同的对策**：任何指标进主表之前先回答三个问题——
① 随机能拿多少分？② 把真值喂进去能拿多少分？③ 要比的两组置信区间会不会重叠？

## 墙 4：非配对区间会浪费掉一到两个数量级的统计效率

| 项目 | 非配对结论 | 配对结论 |
|---|---|---|
| facial | 自模型 80.3% vs oracle 81.7%，Wilson 区间大幅重叠，**不能说有差别** | McNemar **p = 0.003**（17 条只有 oracle 对、3 条只有自模型对） |
| starvla | — | 多步历史观测 84% → 91%，McNemar **p = 0.034** |
| seamless | 平滑前后 73.0% vs 75.9%，各自区间重叠 | 同一批句子配对差 **+5.8 个百分点 [+2.5, +9.1]** |

所有消融评的都是**同一个测试集**。各自算区间再看重不重叠，
等于把「两组做的是同一批题目」这个信息扔掉了。

**共同的对策**：同测试集上的两组一律做配对检验。
二元结果（成功/失败、判对/判错）用 McNemar 精确检验，连续量用配对自助。

## 墙 5：加数据买到的不是同分布上的精度

| 项目 | 加了多少 | 同分布指标 | 真正买到的 |
|---|---|---|---|
| seamless | 400 → 2000 句（×5） | SemAcc 无可测变化（72.3% → 70.3%） | **置信区间减半**（±7.0 → ±3.5 个百分点）、FGD 0.39 → 0.13 |
| facial | babbling 2000 → 50000 组（×25） | ExprAcc 80.3% → **80.0%** | 什么都没买到（结论：2000 组就够） |
| sonic | 单段 → 20 段混训 | 训练过的动作 4.1 cm（本来就好） | **未见动作摔倒率 94% → 25%** |

三个项目、三种「加数据」，答案一致：**同分布上的精度很早就饱和，
加数据买的是覆盖面（sonic）或结论的可信度（seamless），或者什么都不买（facial）。**

sonic 那条给出了最直白的解释：

> 分布宽度就是能力边界，这正是 SONIC 700 小时买的东西。

**共同的对策**：加数据之前先想清楚要买的是哪一种。
如果目标是同分布精度，先做数据量扫描确认没饱和——facial 花几分钟就排除了这条路。

## 墙 6：第一个解释通常是错的

| 项目 | 第一版解释 | 实测 |
|---|---|---|
| sonic | march 抬腿低是「参考不可行」 | 残差模式抬到 98% 不摔 → 参考可行；真因是局部最优 + 骨盆奖励罚掉重心横移 |
| starvla | 「没进盘子」是放置精度不够 | 是**抓取没对准**：成功局闭合误差 11.7 mm vs 失败局 45.6 mm |
| seamless | 语义手势判错是「手指学不动」 | 各关节组的误差/幅度比都是 ~1.0；真因是类别几何上离得太近 |
| seamless | 生成结果抖是「采样噪声」或「权重噪声」 | 两者都无效；抖动是**学到的函数**的性质 |
| facial | 预注册预测「代理指标预测不了 ExprAcc」 | ρ = −0.82（p<0.001），**说法过强**，正确版本见墙 1 |

starvla 那一页的标题就叫「诊断连错三次」。

**共同的对策**：每个解释都要能被一个具体的数**证伪**，而不是听起来合理。
starvla 的说法是：「怀疑哪个模块，就把它的输出直接打印出来」。

## 墙 7：负面结果的比例远高于预期，而且必须记下来

粗数一下四个项目里明确记录的**无效或有害**的改动：

- **starvla**：时间集成（照搬 ACT，单调有害，关掉 +11 个百分点）、辅助定位监督（−62 个百分点）、
  扩散动作头（3.8%）
- **sonic**：RMA 式历史观测（同预算下反而略差）、三个杠杆不叠加（镜像买的是双向能力不是精度）
- **seamless**：推理参数（12 组全无效）、权重 EMA（无效且看训练阶段）、
  Huber 重建损失（无额外贡献）、模型内低通核第一版（有害）、
  我自己提的「按 SemAcc 选检查点」（选出更差的检查点）
- **facial**：串扰几乎没拿走能力（81.7% vs 82.5%，和预期相反）

**在 seamless 这一轮里，训练侧的每一个想法都是中性或负面的，唯一奏效的是一个零成本的后处理步骤。**

**共同的对策**：把「试过、没用」写进文档，和成功的改动同等篇幅。
这些是下一个人最需要的信息，而且**只有做过的人写得出来**。

---

## 一句话

四个任务、四套模型、四种指标，撞到的是**同一批关于「怎么做实验」的墙**，
而不是关于卷积或者 Transformer 的墙。

所以这几个项目真正的产出不是代码，是那张
「先量上限下限 → 配对比较 → 第一个解释先证伪 → 把没用的也写下来」的检查表。
