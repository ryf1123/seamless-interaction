# 怎么把效果做上去：按性价比排的清单

每一条都写清**成本、预期收益、怎么验证、依据是什么**。
已经验证过的（无论有效无效）标了结果，没验证的标了「未试」——不要把预期当结论。

当前主基线（`runs/flow_body`，Mel + 逐帧词 id + flow matching，8000 步）：

```
SemAcc      73.0 %      （随机 7.7 %，真值 100 %）
FGD          0.53
MPJPE        9.53 cm    （采样式模型的噪声底 3.43 cm）
BeatAlign    0.785      （真值 0.659，同密度随机 0.692 —— 这个指标在这里没有分辨力）
抖动 |Δv|    3.83 cm/帧  （真值 0.270 → 14.2 倍）
```

---

## A. 已经验证过的

### A1. 推理参数（CFG 权重 × ODE 步数）——**无效，已排除**

- 成本：0（不用重训）
- 结果：12 组全扫完，抖动倍数落在 **14.59–15.06** 之间，完全没有区别。
- 结论：抖动是**训出来的**，不是采样造成的。这条排除掉之后，剩下的路只有改训练。
- 副产品：CFG = 2.5 的 SemAcc 略高于 1.0（71–74 % vs 67–68 %），
  但差异在这个测试集规模下读不出意义。本项目默认的 1.5 不吃亏。

### A2. 音频条件的表示——**有效，而且是意外收获**

第三环本来是想看「音频对节拍的贡献」，结果读出来的是另一件事：

| 音频条件 | FGD | SemAcc |
|---|---|---|
| `mel` 80 维 log-Mel | 5.05 | 62.0 % |
| `token` 离散语音 token | **0.39** | **72.3 %** |
| `env` 1 维能量包络 | 0.94 | 68.6 % |
| `none` 完全没有音频 | 0.78 | 68.6 % |

同为 5000 步时，**`mel` 的 FGD 是 `token` 的 13 倍**——换句话说，`token` 在 5000 步就达到了 `mel` 训到 8000 步的水平（0.53）。

> 但 **FGD 在 5000 步远未收敛**：同一个配置的两个独立 run 是 5.05 和 6.21。
> 所以这一列读的是**收敛速度**，不是最终质量。

> 一个必要的限定：主基线也是 `mel`，训到 8000 步后 FGD 降到 0.53。
> 所以正确的说法是 **`mel` 收敛更慢，不是不可用**——
> 高维连续条件里有大量与动作无关的高频结构，模型要先花容量学会忽略它。

> **建议仍然是换成 `token`**：同样步数下 FGD 好一个数量级、SemAcc 高 10 个百分点，
> 代价只是配置里改一个词。已排进 `v2` 实验。

> **另一条更重要的**：`none`（完全没有音频）超出随机基线 +0.091，
> `mel` 是 +0.107——**音频在这份数据上几乎没有额外贡献**。
> 因为语音是逐词合成拼接的，包络的峰几乎就落在词的中间，
> 而文本条件已经给了精确的词级时间。要真正测音频的贡献，得让韵律随机化或换真实语料。
> 详见 [`notes/08`](../notes/08-第三环-语音表示.md)。

## B. 正在验证

### B1. 速度损失权重 λ_v 和 Huber 重建损失

- 成本：4 × 5000 步 ≈ 2.5 小时
- 组别：λ_v = 1 / 5 / 20，以及 λ_v=5 + Huber（DiffSHEG 式 7）
- 要看的权衡：把速度损失压到极端，会不会同时把语义手势的幅度也压没
  （SemAcc 掉）。**只看抖动降了多少是不够的。**
- 依据：DiffSHEG 式 (6)(7)(8)，λ_t=10 / λ_v=1 / λ_δ=1。

## C. 未试，但成本低、依据强

### C1. 权重 EMA —— 最该先试的一条

- 成本：几乎为零（每步一次滑动平均，不增加训练时间；已实现在 `si/train.py` 的 `EMA` 类）
- 预期：**明显压抖动**。扩散和流模型里几乎是标配，训练权重每步都在抖，
  用滑动平均权重推理输出会平滑很多。
- 怎么验证：同一配置跑两组，`ema=0.999` 和 `ema=0`，比抖动倍数和 SemAcc。
  检查点里两套权重都存着（`model` / `model_raw`），`load_run(..., raw=True)` 取原始的。
- **坦白**：这是我一开始就该做而漏掉的，而抖动恰恰是当前最大的瓶颈。

### C2. 训练更久

- 成本：线性
- 依据：主基线 8000 步时 val 仍在下降；消融组只跑了 5000 步。
- 注意：SemAcc 可能早就饱和而 val loss 还在降——**要按 SemAcc 判早停，不是 val loss**。

### C3. 更大的训练窗口

- 成本：注意力是平方复杂度，窗口 120 → 180 大约慢 1.5–2 倍
- 依据：测试集里不少句子超过 120 帧，现在要靠 FOPPAS 分段。
  一次生成完整句子能去掉一个误差来源。

## D. 未试，中等成本

### D1. 模型容量

论文是 12 层 / d=1024 / FFN 4096，本项目是 6 层 / d=256（7.4 M）。
16 GB MPS 上大概能到 8–10 层 / d=512。**先做 C1–C3，容量通常不是当前瓶颈**——
主基线在训练集上还没有过拟合的迹象。

### D2. 数据量

400 句 / 33 分钟。翻到 2000 句约 12 分钟就能造完（TTS 缓存已经热了）。
消融的置信区间现在普遍有 ±7 个百分点宽，**光是把测试集从 40 句加到 200 句，
就能让「11.7% vs 14.6%」这种比较变得可判**。

> 这条对**结论质量**的提升可能比对模型分数的提升更大。

### D3. 文本表示换成预训练词向量

现在是从零学的词嵌入表（121 个词）。换成预训练词向量或字符级编码，
才谈得上泛化到没见过的词——这是第七环（泛化边界）的前置条件。

## E. 结构性的，成本高

- **级联 Face2Body / Body2Face**（Seamless Interaction §4.3）：本项目还只做了身体。
- **单向 expression→gesture 信息流 + 梯度截断**（DiffSHEG §3.3）：需要先把表情那一路训起来。
- **接真实数据**（BEAT2 / SHOW / Seamless Interaction 的 dev 子集）：
  合成数据上的结论必须重新验证；这是本项目外部效度的唯一出路。

## 建议的下一步顺序

1. **`token` 音频条件 + EMA + λ_v 的最优值**，一次跑一个组合，8000 步。
   这三条都是零成本或近零成本，预期能同时改善 FGD 和抖动。
2. 把数据加到 2000 句、测试集加到 200 句，**重跑第二环和第一环**——
   现在的置信区间太宽，很多比较下不了结论。
3. 再考虑容量和结构。

## 一条方法上的提醒

这个项目已经两次被「任务设计」而不是模型绊住
（`count1/2/3` 只差手指几乎不可分；确定性数据让「生成式必胜」失效）。
所以每加一个新东西之前，先问：

- 这个指标的**上限**和**下限**分别是多少？
- 数据本身的**噪声底**是多少？模型离它还有多远？
- 我要比的两组，置信区间**会不会重叠**？

三个问题里任何一个答不上来，跑出来的数就读不懂。
